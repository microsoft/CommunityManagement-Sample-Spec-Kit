## Phase 2: Fix (Autonomous)

### Priority 1: Container Startup (Most Likely)

**Common root causes** (investigate in this order):
1. Missing or wrong env vars: `DATABASE_URL`, `NEXTAUTH_URL`, `NEXTAUTH_SECRET`, Key Vault references
2. `api/ready` fails because it tries to connect to a service that's not available in nightly
3. PostgreSQL connection string format incorrect for nightly environment
4. Managed identity (`id-acroyoga-nightly`) missing RBAC role: `Key Vault Secrets User`
5. Application code has a hard dependency (e.g., Stripe, Redis) that's not deployed in nightly

**Fixes may include:**
- Update `infra/modules/container-apps.bicep` env var definitions
- Update `infra/main.parameters.nightly.json` with correct values
- Modify `apps/web/src/app/api/ready/route.ts` to handle missing optional services gracefully
- Add missing RBAC role assignment to managed identity via Bicep
- Add conditional logic in app startup to skip certain checks in nightly environment

### Priority 2: Fix Diagnostics Collection

- Update `.github/actions/deploy-diagnostics/action.yml`
- Add error handling for empty `az containerapp logs show` responses
- Ensure artifacts are uploaded even if JSON parsing fails
- Use fallback to text format if JSON is malformed

### Priority 3: Fix Node.js 20 Warnings

- Update GitHub Actions versions to Node.js 24-compatible releases
- Or add `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24=true` env var if no newer versions available yet

### Priority 4: Fix Bundle Size Check

- Verify correct Next.js 16 path for prerendered HTML
- Fix `grep` pattern if it's failing silently
- Ensure the check reports actual bundle size or fails with clear error
